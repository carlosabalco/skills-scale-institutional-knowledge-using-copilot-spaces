# OctoAcme Project Management Documentation

## Overview
OctoAcme uses a structured, customer-first approach to project management that emphasizes iterative delivery, clear ownership, and data-informed decisions. This documentation collection provides guidance for all stages of the project lifecycle — from initiation through retrospective and continuous improvement — and serves as the single source of truth for process artifacts in the docs/ folder.

## Key Principles
- Customer-first: prioritize customer value and usability
- Iterative delivery: deliver small, testable increments
- Clear ownership: each project has a named Project Manager and Product Lead
- Data-informed decisions: measure impact and iterate based on evidence
- Psychological safety: encourage feedback and learning

## Brief Summary of Project Management Processes
OctoAcme follows a lightweight, repeatable lifecycle: initiation, planning, execution, release, and retrospective. Projects begin with a Project One-pager to capture the problem statement, objective, success metrics, stakeholders, and an initial timeline. Planning breaks approved initiatives into prioritized backlog items with acceptance criteria and a Definition of Done. Execution is tracked via a project board with columns for Backlog, Ready, In Progress, In Review, QA, and Done; PRs are kept small, include acceptance criteria, and run through CI checks and at least one approval before merging.

Roles are clearly defined: Product Managers set outcomes and prioritize work; Project Managers coordinate delivery, manage risks, and facilitate meetings; Developers implement and test code; QA validates acceptance criteria through unit, integration, and end-to-end tests. Communication cadence includes daily standups, weekly delivery syncs, sprint demos, and regular stakeholder updates. Risk management uses a simple risk register with escalation paths from team-level triage up to sponsor-level for business-impacting issues.
